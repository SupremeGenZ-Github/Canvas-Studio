# Canvas Studio+ v3.2.1 — Material Frames

**made by SuprixZ**

This preview updates Living Gallery with eleven frames that require real inventory materials. All v3.2.0 painting, import/export, wall editing, 8×8 placement, animation, ownership, gallery, item-finder and Kurlo Pillow features remain.

## Material frames in v3.2.1

Choose a frame in **Studio menu → Display / access**, then save the painting. Applying or changing a frame consumes **one** matching resource from your inventory, hotbar or off-hand. This cost is per painting, independent of wall size and animation length.

| Frame | Required material (one) |
|---|---|
| Wood | Any item in Minecraft's wooden-planks tag |
| Stone | Stone (not cobblestone) |
| Copper | Copper Ingot |
| Iron | Iron Ingot |
| Gold | Gold Ingot |
| Amethyst | Amethyst Shard |
| Lapis | Lapis Lazuli |
| Diamond | Diamond |
| Emerald | Emerald |
| Quartz | Nether Quartz |
| Netherite | Netherite Ingot |

The editor shows the cost and whether you have the resource. The server validates and spends it **only after a successful save**. Missing material rejects the save and leaves your canvas/painting and resources intact. Cancelled/failed requests spend nothing. Creative mode follows the same material requirement.

Keeping an existing frame while editing, resizing, recoloring or changing animation does not charge again. Old v3.2.0 frames keep their IDs/colors and remain usable. Selecting **None** removes the frame for free; removed/replaced frames do not refund items. Reapplying a removed frame costs again. Frame material is not required just to place or pick up an already framed painting.

CSP projects and gallery entries retain the selected frame design, but they are not proof of payment. Saving them as a new framed painting requires its material. Publishing to the gallery and local previews/exports do not create a framed item and have no charge.

## Appearance, compatibility and safety

Seven new material colors join the existing wood/gold/iron/diamond borders. Existing frame IDs and colors are retained. Borders remain inside the artwork bounds and use decorative geometry rather than new crafting items. No canvas/quill/pillow crafting recipes changed.

The server checks build permission, ownership, bound sessions, wall space and drawing data before invoking the material payment transaction. It checks the inventory before creating maps and spends one resource only after persistence and painting replacement succeed. Both hands and direct wall edits use the same path; completed upload replay guards remain in place.

Use matching v3.2.1 editions on client/server (network protocol 7). Existing CSP formats 1–4, maps and gallery files remain readable. CSP4/CSA1 keep their layouts with frame IDs extended to 0–11; older releases cannot open the new frame IDs, so back up before upgrading and avoid downgrading.

## Validation

Release gates: all 16 Java suites, packaged JAR checks, default/endpoint NeoForge builds, published-family API/range audit and a fresh headless dedicated-server startup/save/stop. The new suite exercises the production payment transaction with real vanilla ItemStacks, every frame/resource and old/new transition, inventory/off-hand positions, missing/wrong materials, failed-save retention, exact consumption, free edits/removal, legacy appearance and file/network codecs.

No interactive client rendering or live player/multiplayer inventory transactions were tested. These are preview builds. See the attached validation report and logs for executed results.

This download targets **Minecraft 26.3 / NeoForge 26.3.x**, including betas. Use the separate JAR for the other Minecraft edition. Metadata accepts future family builds, but future compatibility needs verification.
